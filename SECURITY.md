# Security Policy

FlexRAID is experimental software under active development. Security reports are welcome, and we appreciate responsible disclosure.

## Supported Versions

The current pre-release series is supported for security reports.

| Version | Supported |
| --- | --- |
| `v0.0.x` (including the current `v0.0.0`) | Yes |
| Other versions | No |

Only the current `v0.0.x` development series is supported. Since FlexRAID has not reached `v1.0.0`, interfaces and on-disk formats may change between releases.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub Issues, Discussions, or Pull Requests.**

Use GitHub's private vulnerability reporting feature instead:

1. Open the [FlexRAID Security tab](https://github.com/tetsup/flexraid/security).
2. Select **Report a vulnerability**.
3. Submit the report privately.

Please include as much of the following information as possible:

- The affected FlexRAID version, commit, or branch.
- The environment and configuration needed to reproduce the issue.
- A description of the vulnerability and its potential impact.
- Reproduction steps or a proof of concept, if available.
- Any suggested mitigation or workaround.

If you cannot use GitHub private vulnerability reporting, contact the project maintainers through a private channel before sharing vulnerability details publicly. Do not include sensitive exploit details in a public issue.

## Response and Disclosure

The maintainers will review reports, may request additional information, and will work with the reporter to understand the impact and determine an appropriate fix.

We aim to acknowledge reports and provide updates as promptly as reasonably possible. Response and remediation times may vary depending on the severity and complexity of the issue; no fixed response-time guarantee is made.

Please allow the maintainers a reasonable opportunity to investigate and prepare a fix before publicly disclosing the vulnerability. When appropriate, the reporter and maintainers should coordinate the timing and content of public disclosure.

Security fixes and relevant advisories will be published through the project's GitHub repository and release channels.
